# 项目一文档接入评估与改进

日期：2026-10-17。依据用户提供的两项目录音需求总结，仅评估“项目一：供应商资质核实与检测报告核查”，不把项目二的合同状态、数量或验收日期当作项目一事实。需求总结本身含有推断和待确认项，仍需业务方书面明确一期范围和验收标准。

## 评审结论

ToMarkdown 可以作为受控试点的材料接入组件；0.1.5 不能单独胜任项目一的完整智能审查。0.1.6 增强确定性 Excel 结构保真及来源记录，但尚未完成真实检测报告的质量验收，不能自动认定材料合格。

| 项目一要求 | 当前能力与边界 |
| --- | --- |
| PDF、扫描件、图片、Word、Excel 接入 | 已支持基本转换、OCR 并发与失败返回，原图不缩小；具体版式质量待业务样本验证 |
| 台账字段的准确归属 | XLSX 保留网格、合并锚点、坐标、原值；不猜字段映射或把真空白向下填充 |
| 每个结论可追溯 | evidence 模式提供原文件及输出哈希；XLSX 单元格级，其余格式文件级，PDF Markdown 页码仅作导航 |
| 检测结果、单位、比较符号、跨页表格 | 未通过真实业务样本验收；当前 PDF 非结构化拼接不足以承诺行列关系准确 |

## 已落实的修改

1. XLSX 不再经 DataFrame 猜表头；原始行列、真实空白、原文 `NaN` 和合并引用分别表达。正文 `|` 转义，真实换行使用 `<br>`，字符串、数值、前导零格式、日期和公式分别保留来源信息。
2. 原始 OOXML 可能在合并延续单元格下仍存有值，常规读取库会丢弃。现在同时保留这些值及合并锚点，明确标记 `covered_by_merge` 并提示差异；不能把被遮盖值直接当作可见业务事实。
3. XLSX 来源记录保留隐藏内容、公式及缓存、批注、超链接，嵌入光栅图片按原字节 OCR。图表及图片语义未核验；未识别媒体、无文本返回明确提示复核，未伪造图片框坐标或置信度。
4. `evidence=True` / `--evidence` 输出来源 JSON；原件、结果哈希、工具/依赖版本、模型及提示词摘要绑定到一次转换，不包含密钥。处理期间原件改变会失败。
5. evidence 模式保留输入扩展名，防止同名不同格式相互覆盖；普通模式保持已有命名契约。写入前暂存两个结果，来源 JSON 最后发布；若最终发布失败，移除新输出，避免新 Markdown 与旧来源混配。两文件不是跨进程数据库事务，消费者仍须校验哈希及成功状态。

## 验证事实

- 用户企业清单样本：原始 OOXML 627 个非空存储值、69 个合并区域，全部保留并与原文件逐地址核对。627 个值中有 24 个被合并区域遮盖；常规可见单元格为 603 个。部分被遮盖值与锚点不同，因此必须区分底层存储与显示事实。
- 用户样本的正常网格为 16 个 Excel 列，附带 1 个行号列；被遮盖值另外列出，不再因正文竖线拆错列。原文件不作修改。
- 10 个新增测试覆盖竖线/换行/真空白、合并归属、来源哈希、公式/隐藏页/前导零、同名材料、损坏输入、原始图片字节及 OCR 失败、原件变化、底层遮盖值、空单元格批注和证据发布失败。加上已有 21 项，共 31 项。
- 测试采用确定性假 OCR，不代表真实模型准确率。企业清单是结构回归样本，不代表检测报告质量验收集。

## 项目一建议接入方式

保留原件；调用 `convert(..., evidence=True)`；读取 Markdown 作为检索与模型输入，读取 JSON 作为来源和网格结构。按材料类别抽取字段时绑定 `source.sha256 + sheet + coordinate`，合并引用必须落到对应锚点，不把重复展示当作多条记录。对 `covered_by_merge`、公式缓存、未定位图片等内容保留待复核状态。

规则检查放在上层：台账原字段、材料抽取值、标准版本/条款、比较关系、结论和专家修正分别保存。转换失败、字段未知或证据不足时，不能生成“通过”。没有验证的真实性与生产能力不能从 OCR 文本直接推导。

## 下一步业务验收

补充（0.1.7）：XLS 也已接入单元格级来源记录，保留合并、原值、类型、格式和隐藏状态；用户“关键参数”样本的 249 个非空值、33 条记录全部对应，零模型调用。旧 XLS 的公式只读取保存结果，嵌入图片仍未提取，均有明确警告。原生文字按需解析，首次真正请求 OCR 才初始化模型和检查密钥。详见 [Agent 接入约定](agent-ingestion.md)。
